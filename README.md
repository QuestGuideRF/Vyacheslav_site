# domninvyacheslav.ru

Современный двуязычный персональный сайт-портфолио Домнина Вячеслава Игоревича с живой GitHub-статистикой, SEO-структурой, формой обратной связи, админ-панелью и архитектурой под обычный shared hosting REG.RU.

Проект сделан как полноценная публичная площадка разработчика, а не как простая страница "о себе". На главной странице собраны hero-блок, личная карточка, раздел "Обо мне", таймлайн пути, проекты, блок "Чем я могу быть полезен", GitHub-аналитика, стек технологий, посты, планы, контакты и форма связи. В шапке есть быстрое меню по якорям, переключение языка `RU/EN` и тёмная/светлая тема.

## Что внутри

- Одностраничный публичный сайт с детальными страницами проектов и постов.
- Полноценная админ-панель для управления блоками, проектами, постами, контактами и SEO-настройками.
- Автоматическая инициализация базы и базового контента при первом запуске.
- Двуязычный контент: русская и английская версии сайта.
- Перевод текстов через встроенный `TranslationService`.
- Живая GitHub-статистика по аккаунту `QuestGuideRF` через GitHub API.
- Собственные SVG-виджеты GitHub без внешних `iframe` и без CORS-зависимости.
- Форма обратной связи с сохранением сообщений в MySQL.
- Отправка заявок из формы в Telegram через бота.
- SEO-пакет: `robots.txt`, `sitemap.xml`, Open Graph, JSON-LD, `llms.txt`, `llms-full.txt`.
- Кастомная страница `404`.
- Адаптивный интерфейс, светлая и тёмная тема, анимации и scroll-эффекты.

## Ключевые возможности

### Публичная часть

- Главная страница строится из контентных блоков и данных из базы.
- Поддерживаются отдельные страницы проектов: `/projects/{slug}` и `/en/projects/{slug}`.
- Поддерживаются отдельные страницы постов: `/posts/{slug}` и `/en/posts/{slug}`.
- Навигация закреплена сверху и позволяет быстро переходить по секциям.
- Аватар и изображения загружаются в `uploads/`, для аватаров есть оптимизированные версии.

### Админ-панель

- Авторизация администратора через `/admin/login`.
- Dashboard с GitHub-сводкой и обновлением статистики.
- Управление настройками сайта и SEO-полями.
- Редактирование контентных блоков главной страницы.
- CRUD для проектов.
- CRUD для постов.
- CRUD для контактов.
- Просмотр входящих сообщений из формы.

### GitHub-интеграция

- Получение профиля пользователя через GitHub REST API.
- Сканирование публичных `owned`-репозиториев аккаунта.
- Подсчёт:
  - количества репозиториев,
  - звёзд,
  - подписчиков,
  - активных направлений,
  - распределения языков.
- Кеширование GitHub-ответов в `storage/cache`.
- Встроенные SVG-виджеты:
  - `/github/widget/stats/dark`
  - `/github/widget/languages/dark`
  - `/github/widget/stats/light`
  - `/github/widget/languages/light`

### SEO и индексируемость

- Генерация `sitemap.xml`.
- Генерация `robots.txt`.
- Генерация `llms.txt` и `llms-full.txt` для AI/LLM-индексации.
- Раздельные title/description/keywords для RU и EN.
- Open Graph и Twitter meta.
- JSON-LD для `Person`, `ProfilePage` и `WebSite`.

## Архитектура

Проект написан без тяжёлого фреймворка, на собственной лёгкой MVC-структуре:

- `app/Core` — базовые классы приложения, роутер, запрос, ответ, view, база.
- `app/Controllers` — публичные и административные контроллеры.
- `app/Repositories` — доступ к данным.
- `app/Services` — бизнес-логика, GitHub, Telegram, перевод, загрузки, автоустановка.
- `app/Views` — шаблоны публичной части и админки.
- `assets` — CSS, JS и статические ассеты.
- `uploads` — загруженные файлы и аватары.
- `storage` — кеш, логи, служебные данные установки.

## База данных

Используется MySQL 8. Текущая схема содержит 7 основных таблиц:

- `admins` — администраторы сайта.
- `settings` — общие настройки, SEO, контакты, GitHub и Telegram-параметры.
- `content_blocks` — блоки главной страницы.
- `projects` — карточки и страницы проектов.
- `posts` — посты и обновления.
- `contacts` — выводимые контакты.
- `messages` — входящие сообщения из формы.

Схема лежит в `app/Config/schema.sql`.

## Как работает установка

Проект рассчитан на развёртывание на обычном хостинге REG.RU с PHP и MySQL. Отдельная мастер-страница установки не нужна: приложение умеет само создавать таблицы и заполнять базовый контент при первом запуске.

### 1. Загрузите файлы на хостинг

Загрузите проект в корень сайта, например:

```text
/var/www/uXXXX/data/www/your-domain.ru/
```

### 2. Настройте конфиг

Создайте `app/Config/config.php` на основе `app/Config/config.example.php` и пропишите:

- домен,
- параметры MySQL,
- логин и пароль администратора,
- базовые настройки приложения.

Пример:

```php
<?php

return [
    'app' => [
        'name' => 'domninvyacheslav.ru',
        'base_url' => 'https://domninvyacheslav.ru',
        'timezone' => 'Europe/Moscow',
        'locale' => 'ru',
        'fallback_locale' => 'en',
        'session_name' => 'domnin_portfolio',
        'cache_dir' => dirname(__DIR__, 2) . '/storage/cache',
        'log_dir' => dirname(__DIR__, 2) . '/storage/logs',
        'uploads_dir' => dirname(__DIR__, 2) . '/uploads',
        'install_lock' => dirname(__DIR__, 2) . '/storage/install/installed.lock',
    ],
    'db' => [
        'host' => 'localhost',
        'port' => 3306,
        'database' => 'domnin_portfolio',
        'username' => 'db_user',
        'password' => 'db_pass',
        'charset' => 'utf8mb4',
    ],
    'setup' => [
        'admin_username' => 'admin',
        'admin_password' => 'strong_password',
        'admin_name' => 'Administrator',
    ],
];
```

### 3. Откройте сайт

После первого открытия:

- создадутся служебные директории,
- применится SQL-схема,
- создастся администратор,
- заполнятся стартовые настройки, блоки, проекты, посты и контакты,
- появится `storage/install/installed.lock`.

### 4. Войдите в админку

Адрес входа:

```text
https://your-domain.ru/admin/login
```

Используйте логин и пароль из секции `setup` в `app/Config/config.php`.

## Настройка GitHub

В админке или в таблице `settings` укажите:

- `github_username`
- `github_token` — опционально, но желательно для более стабильной работы и защиты от rate limit.

После этого сайт будет:

- подтягивать профиль,
- сканировать публичные репозитории,
- считать сводную статистику,
- строить языковую аналитику,
- кешировать результаты на 30 минут.

Если токен не указан, GitHub-блок будет работать по публичному API и может упираться в лимиты запросов.

## Настройка Telegram-уведомлений

Чтобы сообщения из формы приходили в Telegram, нужно указать:

- `telegram_bot_token`
- `telegram_chat_id`

После этого каждое сообщение из формы:

- сохранится в таблицу `messages`,
- отправится в Telegram через Bot API.

Если Telegram не настроен, форма всё равно будет сохранять обращения в базу.

## Переводы

Для ускорения наполнения админка использует `TranslationService`, который умеет переводить тексты из RU в EN через MyMemory API. Это позволяет быстро заполнять англоязычные версии блоков, проектов и постов, а затем вручную доработать стиль формулировок.
